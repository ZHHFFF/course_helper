# 实验结论：Flutter 的 `Transform.scale` 能否复现上游 `layerBlock`？

> 实验代码：`lib/experiment/layer_block_experiment.dart`
> 构建：CI run #76，产物 `exp-layerblock-76-a00a9d5-arm64.apk`
> 基线：`refs/kyant/DrawBackdropModifier.kt`（Kyant0/AndroidLiquidGlass @ 65ab177…）
> 设备：一加 13 / Android 15 / dpr 3.5 / Impeller Vulkan

---

## 实验设计

**只切换「缩放机制」这一个变量**，其余完全相同：

- 同一份折射 shader（`liquid_refract_dispersion.frag`）
- 同一组 lens 参数（`10dp*progress` / `14dp*progress` / `CA=true` / `depthEffect=false`）
- 同一形状（Capsule）、同一位置、同一背景

| 模式 | 结构 |
|---|---|
| **A** | `Positioned(190×76) → Transform.scale → ClipRRect → BackdropFilter` |
| **B** | `Positioned(190·s × 76·s) → ClipRRect → BackdropFilter` |

**测试背景**：青色细横线（每 9 逻辑 px）、洋红细竖线（每 13 px）、30px 大字、
11px 小字、18px 彩色字、4 个几何图形（方/圆/三角/十字）、棋盘格。

## 逐项判定

### A：`Transform.scale`

| 判据 | 结果 |
|---|---|
| ① lens 外轮廓变大 | **是**（diff 图可见胶囊轮廓扩大） |
| ② backdrop 采样几何改变 | **是** —— 采样区域跟随变换后的边界一起扩大（否则不可能与 B 逐像素一致） |
| ③ 内部内容放大 | **否**（线间距 31.4px 不变、三角 85px 不变） |
| ④ 其它 icon 被放大 | **否** |
| ⑤ 明显位图缩放模糊 | **否**（与 B 逐像素相同；若是拉伸位图，高频能量会显著下降） |

### B：实际 `width/height`

| 判据 | 结果 |
|---|---|
| ① lens 外轮廓变大 | **是** |
| ② backdrop 采样几何改变 | **是**（采样区域就是放大后的实际区域） |
| ③ 内部内容放大 | **否** |
| ④ 其它 icon 被放大 | **否** |
| ⑤ 明显位图缩放模糊 | **否** |

## 结论

### 1. A ≡ B（Flutter 里两者等价）

`Transform.scale` 包住 `BackdropFilter` 时，**采样输入区域会跟随变换后的边界一起变化**，
因此结果与「直接放大布局尺寸」**逐像素相同**。

→ **`Transform.scale` 是 `layerBlock` 在 Flutter 里可行的等价物**（就"外轮廓 + 采样几何"而言）。

### 2. 但两者都**没有**复现上游的「内部内容被放大」

这是本次实验最重要的发现。

| | 上游 `layerBlock` | Flutter A / B |
|---|---|---|
| 机制 | `graphicsLayer(layerBlock)` 缩放 **node 图层**；backdrop 先按 **node 原始尺寸**渲染进 `innerLayer`，再整体缩放 | `BackdropFilter` 按**变换后的边界**重新采样 |
| 结果 | 采样区域不变，**内容被放大**（1.393×） | 采样区域变大，**内容 1:1 不变** |

**即：上游是「把已渲染的玻璃放大」，Flutter 是「换一块更大的玻璃」。**

→ 因此 **Flutter 侧无法仅靠布局/变换复现上游的放大**。
若要复现，**只能回到 shader 级 zoom**（第一部分按"忠于上游"删掉的 `u_zoom`）。

### 3. 给后续阶段的建议

- **外轮廓与采样几何**：用 A（`Transform.scale`）或 B 都可以，二者等价。
  建议用 **B（实际尺寸）** —— 它不依赖变换与滤镜的交互细节，行为更可预测，
  且圆角半径可直接按新尺寸算（`h/2`）。
- **「内部内容被放大」**：需要单独决策 ——
  - 方案 1：接受"更大的玻璃、1:1 内容"（偏离上游视觉）
  - 方案 2：重新引入 shader 级 `u_zoom`（偏离"只用上游参数"，但能拿到上游视觉）
  - 方案 3：等上游是否有别的机制（如 `LayerBackdrop.inverseTransform` 的补偿方向）需要进一步核对

## 附：实验方法的教训

**测试背景用周期性网格是设计缺陷** —— 折射位移接近整数个周期时，肉眼几乎看不出差异，
容易误判成"lens 没渲染"。本次靠**拖动前后 diff** 才发现 lens 一直在工作。

后续实验背景应加入**非周期性**内容（随机纹理 / 单根粗线 / 大色块边界），
并**以像素 diff 而非肉眼作为判定依据**。
